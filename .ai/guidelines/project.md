## One Piece Cards API – Project Knowledge

- `CLAUDE.md` is generated by Laravel Boost; never edit it by hand. Change `.ai/guidelines/*.md`, then run `php artisan boost:update`.
- This repo is public: `CLAUDE.md`, `.ai/`, `docs/` hold no hosts, users, paths on the server or tokens.

### Purpose

- REST API (`/api/v1`) and MCP server (`/mcp`) for One Piece TCG cards, live at `https://cards.optcg.ch`. Data: Bandai card list via [vegapull](https://github.com/Coko7/vegapull), stored in SQLite.
- Clients are the maintainer's own apps and MCP clients, one Sanctum token each.
- History of the domain move: `docs/plan.md`. Server, deploy, checks: `docs/deployment.md`.

### Commands

- `composer run setup`, `composer run dev`, `php artisan test --compact`, `vendor/bin/pint --dirty`. No browser tests.
- Local card data: `php artisan cards:fetch` (needs `vega` on `$PATH` or `VEGAPULL_BINARY`, takes minutes) or `cards:import <path>`.
- Local token: `php artisan token:create "App" "app@example.com"` (`token:list`, `token:revoke`).

### Conventions

- Minimum PHP is **8.3** (`composer.json`, CI): no PHP 8.4+ features. The PHP version under Foundational Context is the local PHP of whoever ran `boost:update`.
- REST (`CardsController`, `PacksController`) and MCP tools (`app/Mcp/Servers/CardsServer.php`) mirror each other; change both together.
- Card filters only in `Card::scopeApplyFilters()` / `Card::ARRAY_FILTER_PARAMS`, used by REST and MCP.
- `Card` key is the string card id (`OP01-001`); alt arts are own rows (`OP01-001_p1`, `alt_art_variant` set).
- Every Artisan command needs `tests/Feature/Commands/<CommandName>Test.php` (arch test).
- Tests fake vegapull and SSH with `Process::fake()`; fixtures in `tests/Fixtures/vegapull/json`. Never call the real `vega`.
- Docs-only or test-value-only changes need no OpenSpec change; use a `docs/<topic>` branch. Never rewrite `openspec/changes/archive/`.
- `feat` and `fix` commits go into `CHANGELOG.md` (git-cliff): write them for users.

### Deploy (details: `docs/deployment.md`)

- Only the maintainer deploys, by hand: `./deploy.sh`, `php artisan cards:sync`, `./create-token.sh`. No CI deploy.
- Never by an agent: these commands, SSH, DNS, or edits on the server (a dirty server tree breaks the next deploy).
- The production database is never copied in either direction.
- The weekly import job in `routes/console.php` stays in code but is off in production; do not enable it without the maintainer.
- `op-cards.ditshej.ch` is shut down; do not reintroduce it.

### Data and pitfalls

- Docs and `.env*.example` use placeholders only (`<ssh host>`, `<test token>`). Test data is invented, e-mails on `example.com`.
- Event cards: missing cost is imported as `0`; `cost=0` is a valid filter.
- `docs/dev-setup.md` is a generic checklist, not this project's setup; it is in `.gitignore`, so edits are not staged.
